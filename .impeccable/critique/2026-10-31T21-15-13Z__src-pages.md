## Anti-patterns verdict

**LLM assessment:** the composition is not AI slop: sidebar, dense rows, Inter, slate. The tells are broken craft: white hairlines, `[object Object]`, `system:identity-resolution — · —`, an unstyled control in the builder. Sign-in is the exception, with the stock logo tile, heavy wordmark, tagline and card stack.

**Deterministic scan:** 4 CLI findings, all in `src/components/RatingsForm/RatingsForm.module.css`: off-palette indigo at lines 12-13 (genuine drift) and radius at lines 14 and 38 (a conflict inside DESIGN.md, which specifies that radius for inputs but omits it from its scale). The browser overlay's real findings are low contrast from white on primary, a skipped heading on Media (h1 to h3), and an over-long line on System at 1440px.

**False positives:** overused-font, single-font and flat-type-hierarchy are mandated by DESIGN.md's one-family and fixed-scale rules. dark-glow and thin-border-wide-shadow are its documented shadow vocabulary. ai-color-palette fires on the brand teal regardless of use. clipped-overflow-container on Media is unverified.

**Visual overlays:** injection succeeded on every surface in a headless browser, so no overlay is visible to the user.

## Overall impression

The bones are good, and Runs largely delivers the product promise of showing what ran and what changed. Three things undermine it: the builder cannot select a query when there are several, a failed load is indistinguishable from having no data, and a theme defect silently removes every tinted state cue. Fixing the token mechanism and adding one state-handling pattern would recover most of the score.

## What's working

- **Runs detail:** status badge, inline skip reason, expandable targeted titles, a "removed" badge on items gone from their source.
- **Setup checklist:** one next action, earned numbers, semantic list with `aria-current="step"`.
- **Reset control and Media's empty states:** type-to-confirm with clear scope; three distinct empty causes, each with a next step. Keyboard focus reaches every control with a visible change, confirmed by both assessments.

## Priority issues

**[P0] The automation builder has no query picker.** `src/components/AutomationQueryList/index.tsx:54` renders the query id as text and `:92` discards the query list; `src/components/AutomationBuilder/index.tsx:174` preselects only when exactly one query exists. With two or more saved queries, `Add query` yields a row reading "0" that nothing can change, and Create stays disabled. This blocks the in-scope "one or more include/exclude queries" requirement. The MVP's one-query destination scenario would not catch it. **Fix:** a labelled select of query names, styled with the form vocabulary. Behaviour change; needs a test. Suggested command: /impeccable harden.

**[P1] Load failures look like empty data.** With every GET returning 500, Providers says "Connect your first provider", Automations "No automations yet", Runs "No runs yet", System "No system automations", and Media a bare "0 movies". Automations also shows its empty state while loading and System shows nothing. No surface showed an error or retry after 12 seconds. This can prompt someone to rebuild configuration that still exists. Sites: `src/pages/automations/index.page.tsx:152,202`, `src/pages/runs/index.page.tsx:35`, `src/hooks/useAutomationRuns.ts`, `src/pages/settings/index.page.tsx:41,91`, `src/pages/system/index.page.tsx:51-60`, `src/pages/media/index.page.tsx:564,645`. **Fix:** one loading/error/empty/ready pattern with a retry. Behaviour change; needs tests. Suggested command: /impeccable harden.

**[P1] Mutation failures are silent (source only).** `AutomationBuilder/index.tsx:192,233,503`, `src/pages/automations/index.page.tsx:76-79,120-122,172-177`, `src/pages/settings/index.page.tsx:46-49,116`, `SaveQueryDialog/index.tsx:51-52`. A save or delete can fail with nothing shown, and the dialog closes before the outcome is known. **Fix:** return promises, inline `role="alert"`, keep input on failure. Behaviour change; needs tests. Suggested command: /impeccable harden.

**[P1] Tailwind opacity modifiers on theme colours generate no CSS.** `src/styles/theme.ts:332` maps colours to bare `var(--x)`. Both assessments confirmed this in the browser. About 60 uses across 15 components lose their tint: borders fall back to light grey, the destructive confirm has no amber, Reset has no red, a selected task has no fill, and disabled primary buttons read as enabled ghost buttons. **Fix one mechanism:** channel-based tokens with `rgb(var(--x) / <alpha-value>)`, then re-check every surface because all tints switch on at once. Visual; verify by screenshot. Suggested command: /impeccable polish.

**[P1] Below 640px the app is not operable.** Providers, Automations, Runs and System have no navigation at 400px; Settings, System and Sign out are unreachable from anywhere; automation rows lose Run Now, Disable and Delete; Runs needs an unhinted sideways scroll. Sites: `AppLayout.module.css:6`, `src/pages/media/index.page.tsx:765`, `AutomationRow/index.tsx:101`. Neither the plan nor PRODUCT.md says what a phone should be able to do. Suggested command: /impeccable adapt.

**[P1] Automations misstates its own state.** System automations are listed beside the owner's (`src/pages/automations/index.page.tsx:45,53`), so the header says "2 active" while the checklist says none exist. A row shows when it ran but not that it failed (`AutomationRow/index.tsx:87-98`). Status dot is colour-only and hidden from assistive technology. Raw task id at `:67`. Copy "Each automation targets one query" contradicts multi-query. Mostly behaviour; needs tests. Suggested command: /impeccable clarify.

**[P1] Blast radius can be bypassed and is missing where it matters.** The confirm enables with no number, "counting affected items…" sticks forever with no query chosen, and "couldn't count" can still be confirmed (`AutomationBuilder/index.tsx:73-79,221-227`). Run Now on a destructive task has no confirmation (`AutomationRow/index.tsx:134-139`). Behaviour change; needs tests. Suggested command: /impeccable harden.

**[P1] Primary and danger tokens fail WCAG AA.** Measured: white on primary 3.74, on primary-hover 2.49; primary text on panel 3.91; danger text on tinted run rows 2.45-2.53; login tagline over backdrop 1.33-2.24; "Missing" label 2.89. Row dividers are 1.0 on the panel. **DESIGN.md itself specifies white on #0d9488 with a lighter hover, so it conflicts with its own 4.5:1 rule, and the two binding documents need reconciling.** Visual. Suggested command: /impeccable colorize.

## Persona red flags

**Alex (power user):** cannot choose among several queries; no shortcuts or bulk enable/disable/delete; every row action needs hover then a tiny target; no jump from a failing automation to its runs.

**Sam (accessibility-dependent):** focus is visible, but there is no skip link, no `aria-current` in the sidebar, empty document titles, an unlabelled custom-cron input, colour-only status, repeated "Run now" names with no context, and truncated errors available only on hover. Skeleton and spinner animation ignore reduced motion: only 2 files honour it.

**Jordan (first-timer on Automations):** the checklist is clear within seconds, then two `system:` rows suggest automations already exist. "Open settings" lands on a page called Providers. `+ New automation` looks enabled but is not. "Tags: 1" and `[object Object]` undermine trust.
